# Sports Library

## Overview

This library provides base for managing sport events such as football, ski jumping, etc.

## Core concepts

### Match

`Match` stores all facts as events in `Timeline`. State and statistics are projections of this timeline.

Important behaviors:

- Current state of the match (`Scheduled`, `InProgress`, `Finished`, etc.) is determined by timeline events.
- Score updates come from score payloads (`IScoreEventPayload.Apply`).
- Winner is calculated through `IMatchResultStrategy`.
- Disqualifications are a core concept (`IDisqualificationEventPayload`, `Match.Disqualify`) and excluded from winner resolution.

### Score

`IScore` has one required value: `GetValue()`. This is the comparable projection used by generic winner and ranking strategies.

### Tournament

A tournament is a collection of matches that are played by contestants.

- `SingleTournament`: one stage with matches generated by `IMatchesStrategy`.
- `MultiTournament`: multiple child tournaments driven by `ITournamentStrategy`.

Ranking is explicit via `IRankingStrategy`.
`SingleTournament.End()` applies ranking and final ordering.

### Timeline

Another core concept of this library. Timeline is a list of events that happened during a match. It is a base for informations about the match. Timeline can be used to track the progress of the match, determine the winner of the match or state of the match. 

#### Event payload

An event payload is a data structure that contains information about an event that happened during a match. For example, in football, a goal scored event payload would contain information about the player who scored the goal, the time of the goal, etc.

Payloads that bind to a contestant should implement `IContestantEventPayload`. This lets the core `Match` aggregate validate participation without depending on sport-specific payload types.

If a payload disqualifies a contestant, it should implement `IDisqualificationEventPayload`. This enables generic winner filtering and sport-agnostic disqualification queries on `Match`.

## How to add a new sport

### 1. Define sport score type

Implement `IScore` for the value used to compare contestants.

Guideline:

- keep only winner-relevant data here,
- keep diagnostics and timeline details in payloads/trackers.

### 2. Define timeline payloads

Model sport events as payload classes:

- implement `IEventPayload` for informational events,
- implement `IContestantEventPayload` when payload references a contestant,
- implement `IScoreEventPayload` when payload changes projected score.

Guidelines:

- `Apply` must be deterministic and depend only on `current` and payload data.
- Payloads must be simple, they should represent a single fact.

### 3. Decide winner strategy

Choose one of:

- use the default `PenaltyPresentMatchResultStrategy`,
- inject a custom `IMatchResultStrategy` into `Match`.

### 4. Add tournament strategies

Implement what your competition format needs:

- `IMatchesStrategy` for match generation and round progression,
- `IRankingStrategy` for standings/tie-break rules,
- optionally `ITournamentStrategy` for multi-stage events.

Typical mapping:

- league table/group stage: custom ranking strategy,
- elimination bracket: `IMatchesStrategy` + winner-based advancement,
- season with phases: `MultiTournament` + `ITournamentStrategy`.

### 5. Add sport helpers (optional but recommended)

If your sport needs rich read-side queries (cards, periods, attempts, fouls), add a tracker/controller pair in the sport module.

Pattern used in football:

- timeline listener builds in-memory projections,
- controller exposes query API.

This keeps `Match` generic while giving sport-friendly APIs.
